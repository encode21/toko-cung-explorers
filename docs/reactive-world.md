# Reactive World Engine V1

Operational events influence the existing world. No orders, shipments, roles, rewards, player transforms, road layouts, or SceneTime settings are generated by these visual reactions.

## Development

For an explicit development demo, set `VITE_REACTIVE_WORLD_SOURCE=MOCK`, restart Vite and append `?worldDebug` to the world route. The collapsible development panel shows source, host/follower, revision, named active events, actual additional NPC counts, demo countdown, and source errors. Selecting an event does not activate it: click Aktifkan / perbarui. Manual activation starts immediately; the staged demo intentionally begins with 30 seconds of NORMAL. Cooldown rejection is displayed instead of silently ignoring a click. The elected traffic host can activate/update any of the three events, change intensity, choose parcel tier/courier, deactivate, force NORMAL, or start the four-minute demo. Follower controls are disabled.

The demo adds STORE_RUSH at 30 seconds, WAREHOUSE_RUSH at 90, COURIER_PICKUP at 150, and returns to NORMAL at 240. Event deactivation respects a 60-second minimum; expired activations have a 30-second cooldown. Force NORMAL bypasses these constraints for QA. A reserved delivery still finishes its safe route. Configuration is centralized in `src/game/reactive-world/model.ts`.

MOCK state is shared through the existing `world:<room>` channel and has no persistence after all participants leave. The source controller is dynamically imported only in development; the debug component is also excluded from production. A follower never treats ordinary player broadcasts as LIVE business data.

## Integration

- `reactive-world/model`, `store`, `runtime`, `mock`, and `pickup`: normalized contracts, revision/freshness checks, smoothed selectors, source lifecycle, host controls, and delivery progression. Runtime updates at 5 Hz outside React Three Fiber; source polling is not per frame.
- Existing `Npc` controller: temporary slots use the same avatars, dialogue registration, animation, collision, and movement. At most four customers plus one helper on standard quality; at most two customers and no helper on LOW. An anchor is reserved before mounting, must be outside the camera frustum or fully hidden behind opaque scenery, and clear of actors/player, and is released after registration. Customer entries include existing interior route waypoints and sidewalk approaches, so watching the entrance does not indefinitely block arrivals. Five occlusion samples cover the body; glass, hidden meshes, and avatars are not accepted as cover. Customers leave along a separate sidewalk route beyond the entrance view. NPCs complete their visit and exit outside view before removal. Looking continuously at an exit intentionally delays removal and reuse of that slot.
- Existing `NakamaOps` and `ActivityProps`: faster work pauses, visual packing cycles, and bounded parcel piles (2/5/8 boxes). Visual cycles never call `queueOrder`, `startPacking`, `takePalletBox`, or `shipPackage`. Real orders retain priority. Existing trolley/tape/carton cues follow worker activity.
- Existing `ops-store` and traffic snapshots: one `delivery` entity, existing approved routes and collision/FIFO rules. Pickup carries `{eventId, stage, stageAt}`; stages are incoming, pickup, returning, leaving, done. Actual courier arrival and conversation completion gate departure. The completed activation remains recorded so later revisions do not replay it. `packingBusy` prevents a pickup from reserving the truck during an existing packing operation. Metadata uses the current traffic broadcast, not another vehicle transport.
- Existing `useWorldChannel`: initial snapshot request, host snapshots, reconnect, and presence election. Reconnecting peers receive a new connection join timestamp and do not preempt a continuously connected host with stale state. Revision history remains in memory across reconnect; switching rooms clears it.
- Existing HUD feed/audio mixer: deduplicated activity messages, bounded chatter/cashier/packing cadence, unchanged user volume and voice/engine limits. SceneTime is read only by the existing audio/environment systems. Event TTL uses UTC timestamps regardless of SceneTime mode.

## LIVE adapter contract

LIVE is the default in development and production. The authenticated World BFF reads Laravel `/api/world/state`; use the Laravel admin `/world-admin` to maintain schedules and quests after applying `2026_10_10_170000_create_world_event_controls.php`. See [shared account integration](shared-account-integration.md). No separate REACTIVE_WORLD_URL/TOKEN is needed in the World project. OFF disables the visuals; MOCK is an explicit development-only override.

`src/services/tokoCungApi/world-state.functions.ts` validates and whitelists the normalized Laravel snapshot. The browser receives no raw POS tables, customer records or API credentials. Revisions and saved event timestamps remain stable between edits; only generatedAt advances on each fetch.

```json
{
  "revision": 42,
  "generatedAt": 1791513600000,
  "events": [
    {
      "id": "store-rush-20261009-01",
      "type": "STORE_RUSH",
      "status": "ACTIVE",
      "intensity": 0.8,
      "startedAt": 1791513540000,
      "expiresAt": 1791513840000,
      "revision": 42,
      "payload": {}
    }
  ]
}
```

- UTC times are integer epoch milliseconds. Revisions are nonnegative safe integers; event revision must not exceed snapshot revision. IDs are 1–100 ASCII letters/digits/underscore/colon/hyphen.
- This is a full snapshot: at most one event per type and three total. Missing events are inactive. Types: `STORE_RUSH`, `WAREHOUSE_RUSH`, `COURIER_PICKUP`; statuses: `INACTIVE`, `STARTING`, `ACTIVE`, `ENDING`; intensity: finite 0–1.
- Optional payload fields: `parcelTier` = LOW/MEDIUM/HIGH; `courier` = JNE/GoSend/Deliveree. Courier labels are metadata; V1 reuses generic vehicle/avatar visuals.
- Keep ID/start time for the same activation. Increment event revision when changing its fields and increment snapshot revision when changing event contents. A successful refresh may retain the revision with unchanged events and a new `generatedAt`. Use a new ID for a new pickup trip.
- Laravel admin owns activation, scheduling, intensity and persistence. Automatic business thresholds are not configured by this admin release. The browser does not infer LIVE events from raw counters.
- Fetch on join/reconnect/foreground and every 45 seconds. `world_event_updated` is an optional invalidation hint on the existing room channel; it can trigger a debounced server fetch but cannot provide trusted event contents.
- Reject outdated revisions, conflicting equal revisions, snapshots older than 90 seconds, or timestamps more than 30 seconds in the future. Last valid state lasts at most 90 seconds since confirmation and never beyond event expiry. Effects then fade to NORMAL; temporary NPCs and a reserved pickup finish safely. LIVE errors never fall back to MOCK.

## Validation

Run `node scripts/check-reactive-spawn.mjs`, `node scripts/check-reactive-world.mjs`, the existing scene-time/world-feedback/state-protocol/world-plan/road-network/traffic-fleet checks, TypeScript, changed-file ESLint, and `npm run build`.

Browser acceptance uses an isolated local transport fixture (Supabase-shaped API backed by BroadcastChannel), with both desktop and touch/mobile viewports. Exercise individual and combined events, visible spawn/exit anchors, conversation during retirement/pickup, legacy delivery contention, late join, follower controls, stale messages, reconnect, host handoff, and failure/expiry. Verify no extra fleet IDs, no simulated business counters, no SceneTime changes, no production debug controls, and no backend tokens in client bundles.

Local tests cover the authenticated Laravel endpoint, adapter, admin edits and failure behavior without calling POS. Live rollout still requires the new Laravel migration and Supabase private-channel policies.
